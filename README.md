# スタログ 便利ツール

スタログに表示されている時間割を、Googleカレンダーへ登録する
Chrome拡張機能です。

非公式ツールです。学校やスタログの運営元が提供・保証するものではありません。
利用にあたっては、対象サービスの利用規約と学校のルールを確認してください。

## できること

- スタログの週次時間割をGoogleカレンダーへ同期
- 連続授業（例: 1〜3限）を各時限の個別予定として登録
- 「スタログ授業」という専用カレンダーを自動作成
- 提出状況の確認
- 非表示にした提出項目の保存と復元
- 実行時点の年度の年度末（4月30日）までの週を同期

## インストール

1. このリポジトリをダウンロードする。
2. Chromeで `chrome://extensions` を開く。
3. 右上の「デベロッパーモード」を有効にする。
4. 「パッケージ化されていない拡張機能を読み込む」を選ぶ。
5. `manifest.json` があるフォルダーを選ぶ。
6. スタログの対象ページを開く。

## Google認証

同期を初めて実行すると、Google Calendarへのアクセス許可を求められます。
内容を確認して、利用者本人が手動で承認してください。

この拡張機能は、承認したGoogleアカウントのカレンダー全体への操作権限
（`https://www.googleapis.com/auth/calendar` スコープ）を要求します。
実際には、カレンダー一覧を読み取り、予定の登録と削除は専用カレンダー
「スタログ授業」だけに行います。GoogleのアクセストークンやログインCookieを、
このリポジトリには保存しません。

OAuth同意画面が「テスト中」の場合、Google Cloud側で利用者をテストユーザー
として登録する必要があります。友達に使ってもらう場合は、利用者のGoogle
アカウントをテストユーザーに追加したうえで、各自が認証画面で承認してください。

Chrome拡張機能用のOAuthクライアントは、拡張機能IDと関連付けられます。
このリポジトリでは公開鍵を`manifest.json`の`key`に設定してIDを固定しています。
Google Cloud側のOAuthクライアントに登録する拡張機能IDは次の値です。

```text
dcjoobamnjnllamenfjidddgohnjohcf
```

友達の環境で認証に失敗する場合は、Google Cloud側のOAuthクライアントに
登録された拡張機能IDと、`chrome://extensions` に表示されるIDが一致しているか
確認してください。

友達に同じ拡張機能IDで使ってもらうため、公開鍵から生成したChrome拡張機能用の
`key`を`manifest.json`へ設定済みです。Google Cloud側のOAuthクライアントに同じ
拡張機能IDを登録してください。秘密鍵（例: `key.pem`）は公開・コミットせず、このリポジトリの
`.gitignore`でも除外しています。`key`を後から追加・変更すると拡張機能IDが変わり、
保存済みの設定が引き継がれない場合があります。

### 友達に使ってもらう場合

#### 公開者が行うこと

1. 公開リポジトリを用意する。個人アカウントで友達に使わせるだけなら、
   GitHubの書き込み権限を渡す必要はありません。
2. [Google Cloud Console](https://console.cloud.google.com/)で、
   `manifest.json` の `oauth2.client_id` に対応するプロジェクトを開く。
3. OAuthクライアントの拡張機能ID（Item ID）に、
   `dcjoobamnjnllamenfjidddgohnjohcf` を登録する。
4. OAuth同意画面の「テストユーザー」に、友達のGoogleアカウントを追加する。
5. Google Calendar APIが有効になっていることを確認する。

OAuth同意画面が「テスト中」の間は、テストユーザーに追加されていない
アカウントでは承認できません。

#### 友達が行うこと

1. GitHubからリポジトリをダウンロードして展開する。
2. Chromeで `chrome://extensions` を開き、「デベロッパーモード」を有効にする。
3. 「パッケージ化されていない拡張機能を読み込む」を選び、
   `manifest.json` が入っているフォルダーを指定する。
4. 友達自身のアカウントでスタログにログインし、時間割ページを開く。
5. 「Googleカレンダー同期」を押す。
6. Googleの認証画面で、友達自身のGoogleアカウントを選ぶ。
7. 表示内容を確認して、Google Calendarへのアクセスを手動で許可する。

「このアプリは確認されていません」と表示された場合は、友達のアカウントが
テストユーザーに登録されていることを確認したうえで、「詳細」から
「アプリに移動」などのボタンを選んで先へ進みます。

承認後は、友達自身が選択したGoogleアカウントのカレンダーが使われます。
公開者のカレンダーやアクセストークンが友達に共有されることはありません。

認証できない場合は、次を確認してください。

- 友達のGoogleアカウントをテストユーザーに追加したか
- 認証画面で別のGoogleアカウントを選んでいないか
- Google Calendar APIが有効か
- `chrome://extensions` にエラーが表示されていないか
- 拡張機能を読み込んだ後、スタログのページを再読み込みしたか

## 必要な権限

- `identity`: Google認証とアクセストークン取得
- `storage`: 提出状況、表示設定、非表示項目の保存
- Google Calendar API: 専用カレンダーの検索・作成、予定の登録・削除

対象サイトは次のスタログページです。

```text
https://portal.iwasaki.ac.jp/lms/*
```

## 注意事項

- この拡張機能は、対象ポータルを利用できる人向けです。
- Google Calendarの予定は、同期対象週の予定を一度削除してから登録し直します。
- 同期対象は、実行時点の年度の4月30日までです。
- スタログの画面構造や仕様が変わると動作しなくなる可能性があります。
- スタログの利用規約および学校のルールに従って利用してください。
- 時間割、氏名、学籍番号、Cookie、アクセストークンなどの個人情報を
  リポジトリへ追加しないでください。

## 開発・変更

JavaScriptの構文確認例:

```powershell
node --check .\content.js
node --check .\background.js
```

変更後は `chrome://extensions` で拡張機能を再読み込みし、対象ページも
再読み込みしてください。
